## 3. 書類ごとの差し込み書式（過去の契約書から確認）

アプリの項目名（`js/presets.js`）との対応。

### ② 請負契約書

| 箇所 | 項目 | 書式 |
| --- | --- | --- |
| 発注者 ●● ●● 様, ●● 様 | `発注者_姓` `発注者_名` `発注者2_名` | 姓・名を別々に差し込む（「様」「, 」やスペースはひな形の文字のまま） |
| 工事名 / 工事名称 | 同上 | 「…様邸 新築工事」の部分はひな形のまま |
| １、工事現場住所 | `建築地` | 地名地番。例の書式「○丁目12番,13番」 |
| 構造 | `階数` | 「木造ガルバリウム鋼板葺**２**階建て」の数字のみ（全角が基本） |
| 1階 / 2階 / 3階 | `面積_1階` `面積_2階` `面積_3階` | 半角・小数2桁 |
| 延べ床面積 | `延床面積` | 自動計算（各階の合計） |
| ( ポーチ・バルコニー ○○㎡ ) | `面積_ポーチバルコニー` | 無い場合は**行ごと削除**（過去の契約書でそうなっている） |
| 請負代金 / 工事価格 / 消費税 | `請負代金` `工事価格` `消費税` | **全角数字・全角カンマ**（例：４０，０００，０００）。工事価格＝請負代金÷1.1、消費税＝差額（自動計算） |
| 支払い（契約時・配筋工事完了時・上棟時・完成引き渡し時） | `支払_契約時` `支払_配筋` `支払_上棟` `支払_完成` | 全角。契約時は通常 1,000,000。完成＝請負代金−他3回（自動計算） |
| 契約日・甲の住所氏名 | — | **空欄のまま（手書き）** |

検証：過去5件（単名2・連名3）で、工事価格＝請負代金÷1.1、延床＝各階合計、完成＝残額 がすべて一致。
**支払配分の基本ルール（社内確認済み）**：配筋工事完了時金・上棟時金 ＝ 請負額 × 30% を10万円未満切り捨て、完成引き渡し時金 ＝ 請負額 − 契約時 − 配筋 − 上棟（残額を1円単位で正確に）。
**変更契約の差額振り分けルール（2026-10-02 社内決定）**：請負契約時の支払内訳はそのまま残し、差額だけを振り分けて上乗せする。
- 配筋工事完了時金 ＝ 請負契約時の配筋 ＋ 差額 × 30%（10万円未満切り捨て）
- 上棟時金 ＝ 請負契約時の上棟 ＋ 差額 × 30%（10万円未満切り捨て）
- 完成引き渡し時金 ＝ 請負契約時の完成 ＋ 差額の残り（差額 − 上の2つの加算額。1円単位で正確に）
- 例：差額 3,229,600円 → 配筋 +900,000／上棟 +900,000／完成 +1,429,600
※過去の請負契約書にはこのルールと異なる配分の例もあるため、「変更前」の金額は必ず実際の請負契約書の数字を使う。

## 5. 「○○様の請負契約書を作って」と指示されたときの手順（Claude 用）

1. ドライブで「顧客管理タスク」とお客様フォルダを検索し、上の表の情報源から値を読む
2. 単名か連名か（発注者2_名の有無）と、ポーチ・バルコニー行の要否を判断する（判断できなければ確認する）
3. 配筋・上棟の金額は基本ルール（請負額×30%、10万円未満切り捨て）で計算し、完成時を残額にする。資金計画書と食い違う場合は報告する
4. 案件データ（`contract-maker-case` 形式の JSON）を作る
   ```json
   {"format":"contract-maker-case","version":1,"name":"○○様","dateStyle":"wareki",
    "values":{"発注者_姓":"…","発注者_名":"…","発注者2_名":"…","建築地":"…","階数":"２",
              "面積_1階":"…","面積_2階":"…","面積_ポーチバルコニー":"","請負代金":"…",
              "支払_契約時":"1000000","支払_配筋":"…","支払_上棟":"…","契約日":"YYYY-MM-DD"}}
   ```
5. 案件データはチャットで渡すか、お客様のドライブフォルダに保存する（**リポジトリには保存しない**）
6. ユーザーはアプリの「案件データ」に貼り付けて読み込み → 各書類を Word 出力
7. 値の根拠（どのファイルのどの数字か）を一緒に報告する。食い違いがあれば必ず伝える

## 6. 書類の受け渡し

- ファイル形式は元の雛形と同じ（.docx の雛形 → .docx で出力）。Google ドキュメント・PDF への変換はしない。
- 元が .doc（Word 97-2003）の書類は、アプリで扱うと .docx での出力になる。.doc が必須かどうかは確認中。
- 完成した書類はチャットでファイルとして渡し、ドライブのお客様フォルダへの保存はユーザーが行う
  （Claude からのドライブへのファイル書き込みは、ファイルサイズの制約で失敗することがあるため）。

## 7. 気づいた点（要確認）

- ②【単名】【〇〇様】請負契約書 のひな形が、特定のお客様の内容（氏名・住所・面積）で上書きされている
- 建築地の区切り表記が書類によって異なる（「,」「、」「区切りなし」）
- 構造の階数が全角（２）と半角（3）で混在している
- お見積りに「外部ポーチ・テラス面積」があっても、請負契約書にポーチ・バルコニー行が無い例がある（記載基準の確認が必要）
- 契約金を事前に受領済みの場合、「（○年○月○日受領済み）」のような行が追加される例がある
